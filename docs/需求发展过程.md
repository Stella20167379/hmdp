## 普通版 

### 登录、短信验证码、登录拦截

从传统的session+cookie+threadlocal 到 redis+cookie+threadlocal，关键在于session在不同tomcat服务器（JVM）中不共通，即多服务器实例下，频繁拷贝同步session信息太费性能。
因此，引入redis，基于token设计查询key，value存储关键用户信息，用作登录凭证。
具体来说，第一重拦截器使用token查询redis，如果结果空则拦截，如果成功则存储进threadlocal（不过为什么要用这个呢，难道没有其他方法吗？）并放行，后续登录拦截器则直接查询threadlocal中用户是否为空即可。
这样做的好处，我想是可以只在登录这种关键步骤中在请求头加token字段，后续无需携带这种敏感信息，直接无感登录使用。
不过也有问题，就是登陆状态的时效问题。什么时候过期呢？
两种常见处理方案。
第一种称为滑动过期（redis自动续期），即拦截器在每次有效请求内刷新token时效（也可设定刷新时效阈值），这种比较简单通用。
第二种成为双token方案，有Access Token + Refresh Token，安全性高，适合金融业务场景。
